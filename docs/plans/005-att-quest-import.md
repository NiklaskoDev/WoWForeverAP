# 005 — Quest data from the AllTheThings Forever database (dev-time import)

Status: approved
Type: feature
Version impact: none — nothing is released yet; entries go under `[Unreleased]` and ship with the first release (001–005).

## Goal
`quests.csv` becomes a generated file. A dev-time tool imports it from the Forever database of AllTheThings (ATT) at a pinned commit. This replaces the 34 provisional WoW-Pro rows with every launch quest in the zones of `zones.csv` that a character of the seed's faction can do. The same run writes a review report that cross-checks `zones.csv` level ranges and the profession tier data against ATT. Those CSVs change only as far as D2 allows. ATT is never a runtime dependency, and its Lua is parsed as data, never executed.

Out of scope:
- Any Wowhead access (robots.txt disallows our agents and a WAF bot challenge blocks requests, which we do not evade).
- New zones in `zones.csv` (cities, Mount Hyjal, Rivergladss, Shendralas).
- Quests in dungeon, class, profession or holiday files of ATT.
- A class or race option.
- Replacing `material_brackets.csv` and `profession_materials.csv`. These are game-design tables, and ATT has no data for them.
- Changes to the CSV schemas or the location-ID scheme. Quest ids stay Blizzard ids, so the existing ids are kept.

## Data
No database and no schema change. `quests.csv` keeps the 001 columns `quest_id,name,zone_ui_map_id,req_level,faction,release,prereq_quest_ids,extra_zone_ids,name_suffix`.

### Import inputs
All inputs are read from `.att/AllTheThings/.contrib/.db/forever/`, or from `--att-root` for tests:
- `zones/**/*.lua` (Eastern Kingdoms, Kalimdor, `zephras isle.lua`): quest source.
- `.nyi/quests.lua`: ids of not-yet-implemented quests. Every `q(<id>` here is excluded wherever it appears.
- `.config/constants/maps.lua`: `MAP` constants. Read them with the line regex `^\s*([A-Z0-9_]+)\s*=\s*(\d+)\s*[;,]`. One name with two different values is an error.
- `.config/.wago/UiMap.<build>.csv`: columns `ID`, `ParentUiMapID` (read by header name) for parent walks. `<build>` comes from the file name. More than one build among the `.wago` files is an error. The game version is the first three parts (`1.60.1`).
- `.config/.wago/SkillLineAbility.<build>.csv`: column `SkillLine`. Used only for the profession report.
- `.config/exports/Skill Level Requirements.lua`: line regex `^\s*\[(\d+)\]\s*=\s*(\d+),?\s*--\s*(.+?)\s*\((Apprentice|Journeyman|Expert|Artisan|Master|Grand Master)\)\s*$` gives (profession name, rank name, learnedAt). Used only for the profession report.
- `apworld/wow_forever/data/zones.csv` and `professions.csv` / `profession_tiers.csv`, through `data_loader`.

### Extraction rules (`import_att.py`)
1. **Own zone.**
   - Every file holds `maproot(...)` calls. Before the table argument there is a continent and a zone, or only a zone. The zone is the last `MAP.*` name or integer argument before the table.
   - Every `q(...)` anywhere inside that call's tree belongs to that zone.
   - If the zone is not in `zones.csv`, all of its quests are excluded (`zone-not-in-data`).
   - A file without `maproot` is an error.
2. **Map resolution** (`resolve_zone(map_id, root_zone, local_maps)`), in this order:
   - the map id itself is in `zones.csv` → that zone;
   - it was declared by an `m(...)`/`maproot(...)` inside the same `maproot` tree → `root_zone` (sub-zones such as `NORTHSHIRE_VALLEY = 425`, which may be missing from the Forever UiMap table);
   - walking `ParentUiMapID` reaches a `zones.csv` id → that zone;
   - otherwise → unresolved.
3. **Fields read** from `q(<id>, { ... })`: `lvl`, `races`, `classes`, `sourceQuest`, `sourceQuests`, `coord`, `coords`, `maps`, `timeline`, `u`, `repeatable`, `isDaily`, `isWeekly`, `isMonthly`, `isYearly`, `isBreadcrumb`, `requireSkill`, `lockCriteria`, `altQuests`, `minReputation`, `maxReputation`. All other fields are ignored.
4. **Name.** The first line comment on the same source line as the `q` identifier, collapsed to one line and capped at 100 characters (e.g. `A Threat Within`, `The Defias Brotherhood (1/7)`). If there is no comment → excluded (`no-name`).
5. **Exclusions.** Each excluded quest is reported with one reason, checked in this order:
   - `nyi`;
   - `unobtainable` (any `u`);
   - timeline. Markers are `TIMELINE.ADDED_a_b_c` / `REMOVED_a_b_c` / `CREATED_a_b_c` (version parsed from the name). The state at the build version is the last marker ≤ the version. Results: `future` (first marker > version) or `removed`;
   - `repeatable` (`repeatable`, `isDaily`, `isWeekly`, `isMonthly`, `isYearly`);
   - `breadcrumb`;
   - `class-restricted` (`classes`), per D4;
   - `race-restricted`, per D4;
   - `profession` (`requireSkill`);
   - `reputation` (`minReputation`/`maxReputation`);
   - `lockable` (`lockCriteria`, `altQuests`), per D4;
   - `map-outside-zones:<id>` (any `coord`/`coords`/`maps` map id is unresolved);
   - `faction-mismatch` (quest faction vs. zone faction, e.g. a Horde quest in an Alliance zone);
   - `id-out-of-range` (native ≥ 10,000,000);
   - `duplicate` (same id found again; the first occurrence in sorted path order wins).
6. **Faction.** `races` is the identifier `ALLIANCE_ONLY` / `HORDE_ONLY` or a table of race identifiers.
   - The tool has its own table: `ALLIANCE = {HUMAN, DWARF, NIGHTELF, GNOME}`, `HORDE = {ORC, UNDEAD, TAUREN, TROLL}`.
   - An unknown identifier is an error naming it, so a new race is added deliberately.
   - Full Alliance set → `alliance`, full Horde set → `horde`, absent → `both`. Any narrower set → `race-restricted` (D4).
7. **Level.** `req_level` = `lvl` if it is an integer, or the first integer argument if `lvl` is a call. Clamp it to 1..60. If it is missing → the zone's `min_level`, and the report lists the quest.
8. **Extra zones.** `extra_zone_ids` = the resolved zones of `coord`/`coords` (third element) and `maps`, minus the own zone, sorted.
9. **Prerequisites.** `prereq_quest_ids` = `sourceQuest` ∪ `sourceQuests`, sorted, kept as all-of (stricter than ATT's any-of `sourceQuestNumRequired`, which is safe for logic). Iterate to a fixpoint:
   - prereq kept → keep the edge;
   - prereq excluded as `repeatable` or `breadcrumb` → drop only the edge;
   - otherwise (other exclusion, or the id is unknown to the zone files) → exclude the dependent (`prereq-excluded:<id>`).
10. **Release.** `release = 1` for every row (only the launch release exists; `future` covers the rest).
11. **AP names.** Kept quests that would share `{zone}: {name}` all get `name_suffix = (#<quest_id>)`. This is stable under re-imports unless a new duplicate appears.
12. **Output order.** Zone row order of `zones.csv`, then `quest_id`.

Header comments of the generated `quests.csv`:
```
# GENERATED by tools/import_att.py - do not edit; re-run the import instead.
# Source: AllTheThings (github.com/ATTWoWAddon/AllTheThings, MIT), .contrib/.db/forever, commit <sha>, build <build>.
# req_level is ATT's lvl (minimum level); release is 1 for every row. Exclusions are listed in data_capture/att_report.txt.
```

### Report `data_capture/att_report.txt`
1. Counts per exclusion reason, with the quest ids and names.
2. Unresolved map ids with the quest count each.
3. Quests per zone and faction.
4. Zone level cross-check: per zone, the `zones.csv` `min_level`/`max_level` against the quest `lvl` minimum, median and maximum. A zone is flagged when `|min_level − min lvl| > 2` or `max_level < max lvl`.
5. Profession cross-check:
   - every `professions.csv` `skill_line_id` appears in `SkillLineAbility.SkillLine`;
   - per profession, the rank names and `learnedAt` from the Skill Level Requirements export, against `profession_tiers.csv`. Flag when the tier count or names differ, or when rank n+1 `learnedAt` > tier n `max_skill`.
   - It also states that ATT has no character-level requirement for tiers and no material data.

## Interfaces
- `scripts/fetch_att.sh` (no args). It exits non-zero if git fails. Steps:
  1. Run `git clone --filter=blob:none --no-checkout --sparse`.
  2. Run `git sparse-checkout set .contrib/.db/forever`.
  3. Run `git fetch --depth 1 origin <sha>` and `git checkout <sha>`.
  4. Print the path.
- `tools/att_lua.py` (pure, no I/O except `parse_file(path)`):
  - Nodes: `AttCall(name: str, args: list, line: int, comment: str | None)`, `AttName(dotted: str)`, `AttOpaque(line: int)`. Tables → `list`/`dict` as in `lua_table`, and their values may be nodes. Literals → Python values.
  - `class _AttParser(lua_table._Parser)`. It overrides:
    - `skip_space`/`_skip_comment` to record line comments as `(line, text)`;
    - `parse_value` to add dotted names, calls (`f(...)`, `f{...}`, `f"..."`), method calls (`a:b(...)`), index chains, `function ... end` bodies (skipped by keyword balance → `AttOpaque`), unary `-`/`not`/`#`, and binary operators (whole expression → `AttOpaque`).
  - `parse_chunk(text, path) -> list[node]`:
    - statements are `local namelist [= exprlist]`, `var = exprlist`, call statements and `;`;
    - `for`/`if`/`while`/`do`/`repeat`/`function`/`local function`/`return` blocks are skipped by keyword balance, respecting strings and comments.
    - Returns the call and assignment nodes in order.
  - `iter_calls(node, name) -> Iterator[AttCall]` (depth-first).
  - `AttParseError(path, line, col, msg)` (wraps `LuaParseError`).
  - Never evaluates, never imports, never calls.
- `tools/import_att.py`:
  - `python tools/import_att.py [--att-root DIR] [--out FILE] [--report FILE] [--check]`.
  - Defaults: `.att/AllTheThings/.contrib/.db/forever`, `apworld/wow_forever/data/quests.csv`, `data_capture/att_report.txt`.
  - `--check`: write nothing, exit 1 if the generated text differs from `--out`.
  - Errors (`AttImportError`, exit 1, one line `error: …`):
    - the root is missing (hint: run `scripts/fetch_att.sh`);
    - the checkout SHA ≠ `tools/att_version.txt` (read `.att/AllTheThings/.git/HEAD`; skipped when `--att-root` is given);
    - a parse error;
    - an unknown race identifier;
    - more than one build;
    - the generated rows fail `data_loader.parse_game_data`.
  - Functions: `load_maps(text)`, `load_ui_map_parents(text)`, `collect_quests(files, maps) -> list[RawAttQuest]`, `classify(raw, ctx) -> Quest row | Exclusion`, `resolve_prereqs(rows, exclusions)`, `assign_suffixes(rows, zones)`, `render_quests_csv(rows, sha, build) -> str`, `build_report(...) -> str`, `main(argv) -> int`.
- If D3 = a, `QuestWeight(Range)` in `options.py`:
  - `display_name = "Quest Weight"`, 1–100, default per D3;
  - docstring: "Percentage of the eligible quests that are checks (at least one when any are eligible)."
  - Added to `WoWForeverOptions` as `quest_weight`.
  - `locations.select_locations` gets `quest_weight: int = 100` and applies `sample_by_weight(quest_specs, quest_weight, rng)`; `__init__.py` passes it.
  - Slot data is unchanged, because the inbox already lists the seed's locations.

## Security and user data
No secrets and no personal data. ATT files are untrusted input:
- they are parsed, never executed;
- the parser has a depth limit (inherited `MAX_DEPTH`);
- names are collapsed to one line and capped at 100 characters, then written with the `csv` module;
- the generated CSV passes the normal `data_loader` validation;
- `Generated.lua` goes through `lua_table.render` escaping as today.

The clone is pinned to a reviewed SHA. Nothing is downloaded at build, test or play time.

## Implemented deviations (review 2026-11-17, recorded by the main session)
Parsing details found in the real ATT files at the pinned commit; none changes the design (import as data, pinned commit, same CSV schema and ids):
- Races: Forever adds Skyborne (`SKYBORNE_ALLIANCE`, `SKYBORNE_HORDE`), so each faction has 5 races; a single race may be written without braces; `exclude(...)` in `races` counts as race-restricted; any `classes` value counts as class-restricted.
- Faction-split quests (`allianceQuestData = q(a)`, `hordeQuestData = q(h)` + shared fields) become two quests with forced factions; `aqd`/`hqd` giver blocks are ignored.
- Faction follows the zones a quest needs: a raceless quest in an Alliance zone is Alliance; a quest needing the other faction's zone is excluded as `faction-mismatch`; a prerequisite of another faction excludes the dependent as `prereq-faction`, a faction-less dependent takes its prerequisite's faction.
- Extra exclusion reasons: `created` (`CREATED_1_60_1` = not yet in game), `outside-maproot` (quests under `root(ROOTS.HiddenQuestTriggers, …)`; they count as unknown prerequisites). A file without `maproot` is an error only if it contains quests.
- Map references may be bare names (resolved via `maps.lua` or `m(...)` declarations; unknown `MAP.X` is an error); timeline markers may lack the `TIMELINE.` prefix; `DELETED` counts as removed; `coords` may be one flat coordinate; `AttAssign` node type for assignment nodes.
- Local helper calls such as `CRAFTSMANS_WRIT_QUEST(...)` are not evaluated (never executed), so those repeatable profession writ quests are absent.
- Fixtures sit under `tests/fixtures/att/` directly.
- Zephra's Isle stays 1–12: ATT quest levels are 2 / 4 / 8 and the report's flag rule (min within 2, max ≥ highest quest level) does not flag it, so ATT does not contradict the range; the `zones.csv` comment cites ATT. Still provisional until the live-client check.

## Risks / follow-ups
- ATT's Forever DB is community-maintained and partly unverified for Forever. The quest data stays "unconfirmed" in the README until checked in the live client (001 D1/D2).
- The ATT syntax may contain forms the parser does not know. Step 5 stops on them instead of guessing. Expect one parser amendment after the first real run.
- `Zephras Isle` exists twice in the Forever UiMap (2521, parent 947, and 2665, parent 0). If ATT's `ZEPHRAS_ISLE` or coords use 2665, those quests are reported as unresolved. The fix is a zones.csv/map decision, not a silent alias.
- Excluding city- and dungeon-linked quests (and all class quests) removes many real levelling quests. A later plan that adds cities or instances to the zone logic can re-include them with no tool change beyond the zone data.
- Only quest-level `coord`/`coords`/`maps` are read. Objective locations nested inside `groups` are ignored, so a quest whose objectives lie in another zone without a quest-level `maps` key is under-constrained in logic.
- `req_level` is ATT's minimum level, not the quest's difficulty. Logic may expect some quests earlier than comfortable.
